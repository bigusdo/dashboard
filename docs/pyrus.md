# Подключение Pyrus (бот MainBot)

Дашборд ходит в Pyrus API (pyrus.com) от имени бота **MainBot**. Секреты в репозиторий не попадают.

## Что нужно
- Логин бота (вида `имя@botNNNN`) — `PYRUS_LOGIN`.
- Секретный ключ бота (`security_key`) — `PYRUS_KEY`.

## Где взять ключ
1. Pyrus → «Настройки» (меню организации) → «Боты» (в части интерфейса — «Интеграция» → «Боты»).
2. Открыть MainBot → блок «Доступ к API»: там логин и секретный ключ. Ключ можно перегенерировать.

## Как выдать боту доступ к задачам
Бот видит только то, к чему ему дали доступ, как обычному пользователю:
1. Добавить MainBot в нужные формы: «Настройки формы» → «Доступ» → дать права на **просмотр и редактирование** (редактирование нужно для ответов и вложений из дашборда).
2. Если задачи видны только участникам — убедиться, что у бота есть доступ к реестру формы.
3. Ответы из дашборда будут подписаны именем бота (MainBot). Если нужны ответы от имени сотрудников — потребуется отдельная схема авторизации, обсуждается позже.

## Как сохранить ключ на этом компьютере
Тем же способом, что и ONEC_USER / ONEC_PASS: пользовательские переменные Windows. Ключ в чат не отправлять.

```powershell
[Environment]::SetEnvironmentVariable('PYRUS_LOGIN', 'логин_бота', 'User')
[Environment]::SetEnvironmentVariable('PYRUS_KEY', 'секретный_ключ', 'User')
```
После этого перезапустить `start.cmd`.

## API (справка)
- Авторизация: `POST https://accounts.pyrus.com/api/v4/auth` с `{login, security_key}` → `access_token`, `api_url`. Токен живёт ~24 ч.
- Формы: `GET {api_url}/v4/forms`; реестр: `GET {api_url}/v4/forms/{id}/register`.
- Задача: `GET {api_url}/v4/tasks/{id}`; ответ/вложение: `POST {api_url}/v4/tasks/{id}/comments`; файлы: `POST {api_url}/v4/files/upload`.
- Ссылка на задачу: `https://pyrus.com/t#id{id}`.

## Правила дашборда
- Показываются только **незакрытые** задачи, сортировка по сроку.
- Метки (списки Pyrus): объект, статус (КП, согласование…), тип работ (слаботочка, СВИК, СМР, прочее) — уточняются по реальной выгрузке форм.
- Из дашборда: ответить на задачу, прикрепить файл, перейти в Pyrus.

## Что реально лежит в Pyrus (выгрузка 2026-10-30)
- Задачи **без форм** (простые задачи); формы и входящие у бота пустые. Работа идёт через **Списки**.
- Бот (`main_bot`, id 953917) состоит в 12 списках: ПИК, СВиК, Слаботочка, Озерки, Адмирал, Галерея, ОП, ЛСР, Охта, Неский 25, Прочие, СМР. Объекты и типы работ — это списки; задача может быть в нескольких (например, `Озерки + Слаботочка`).
- Всего ~606 задач с архивом, из них ~560 закрыты, **48 открытых** (ПИК, СВиК, Слаботочка, Озерки, ОП, СМР).
- Эндпоинты: `GET lists`; `GET lists/{id}/tasks?item_count=200&include_archived=n`; `GET tasks/{id}` (поля: `subject`, `responsible`, `author`, `list_ids`, `due_date`, `is_closed`, `close_date`, `comments[].attachments`, `linked_task_ids`). В выдаче по списку нет `is_closed`, срока и вложений — они только в карточке задачи. `api_url` из авторизации уже содержит `/v4/`.
- Срок (`due_date`) заполнен у малой части задач (у открытых почти нигде).
- Статус КП/согласования отдельным списком не найден: в старых задачах он дописан в заголовок (`... - КП НА СОГЛ`, `ДЕЛАЕМ КП`, `В РАБОТЕ`, `ВЫПОЛНЕНО`); номер КП и договора — в заголовке (`КП1091`, `ДС50`).
- Справочник «Статусы задач» (id 189223): «Ждем ответ от заказчика», «Собираем информацию», «Делаем КП» — к простым задачам не привязан.

## Списки-статусы (бот добавлен, 2026-10-30)
Статус задачи — тоже список Pyrus, задача состоит одновременно в списке объекта, списке типа работ и списке статуса:
- Делаем КП · КП на согласовании · КП согласовано. Заключаем договор! · В работе · Ждем денег! · Оплачено · Выполнено · На паузе до срока!!!
- Объекты: ПИК, Озерки, Адмирал, Галерея, ЛСР, Охта, Неский 25, Прочие. Типы работ: Слаботочка, СВиК, СМР.
- Список «ОП» — внутренние задачи отдела продаж, на дашборде не показываем.
- Сроки (`due_date`) у открытых задач не заполнены; решение по ним — см. ниже в истории изменений.

## Правила ведения задач (от владельца)
- Сроки в Pyrus **не проставляем массово** (чтобы не спамить уведомлениями). Задачи без срока на дашборде считаются просроченными; сроки правятся постепенно по ходу работы.
- В каждой задаче должен быть **номер КП** (формат `КП1091` в заголовке), кроме задач по техобслуживанию — для них позже заведём отдельный список.
- Аудит 2026-10-30: открытых задач без «ОП» — 41; номер КП есть у 26, нет у 15 (список строится скриптом по заголовку, тексту и комментариям).
